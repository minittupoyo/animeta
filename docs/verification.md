# 検証結果

検証日: 2026-10-03。実行環境: Linux x86_64（Arch Linux）、bun 1.4.2、Rust 1.99.0。

## 実施済み

- `bun run check`: Vue・TypeScriptの型チェック成功。
- `bun run test`: 14件成功。対応付け、作品変更時の解除、プレビューの無効化、エラー表示、二重実行の防止、失敗分の再取り込みを確認。
- `bun run test:ui`: 8件成功。作品選択、エピソード編集、命名プレビュー、操作切替、履歴画面、ライト・ダーク、最小幅960px、axeによるWCAG 2 A/AA自動チェックを確認。動きを減らす設定にも対応。説明をヘルプダイアログへ移動し、オンデマンド表示、Enter / Escapeでの開閉、フォーカス復帰、ダイアログのaxeチェックを確認。
- `cargo test`: 27件成功。話数推定、命名の省略区間・桁数、禁止文字・予約名、出力競合、キャンセル・一時ファイルの削除、入力変更の検出、設定保存、履歴の中断復旧、Annictのページ取得・認証エラー・一時エラーからの再試行を確認。
- メディア結合テストには、実際のFFmpeg 8.1系・ffprobeを使用。MP4・MKVのタグを読み戻し、原本のバイト列が変わっていないことを確認。MKVの字幕、音声、添付ファイル、チャプター、トラックの言語・タイトル・再生フラグを確認。
- 再生時間の検証: 映像・音声より長い字幕を持つMKVで、字幕・チャプター削除を有効にして同名上書きする回帰テストを追加。コンテナの時間表示が約3秒から約1秒に変わっても、保持する映像・音声の時間と符号化済みパケットハッシュが一致することを確認。保持トラックの短縮、時間情報の欠落時には公開前に拒否し、エラーに比較秒数を表示。報告された「やがて君になる」の実ファイルとWindows実機での再現は未検証。
- コピー／上書き: 既定のコピーと旧設定の互換性、同名の元動画へのタグ更新、別名への置き換え（MP4 / MKV）、リネームのみ、キャンセル・名前の競合・入力変更時の原本保持、一時ファイルの削除を確認。UIで設定の保存、元フォルダへの出力、出力先入力の非表示、モード変更時のプレビュー失効、処理後のファイル情報更新を検証。上書きモードのWindows実機動作は未検証。
- 字幕・チャプター削除: MP4 / MKVで字幕のみ、チャプターのみ、両方、タグ付与と併用を検証。削除のみの実行、元動画の不変、映像・音声の符号化済みパケットハッシュ、MP4カバー画像・MKV添付ファイルの保持、旧設定の既定値を確認。残存する削除対象や音声欠落を検証で拒否。UIでは単独選択、全処理オフの無効化、設定変更によるプレビュー失効を確認。
- 自動マッチング: `作品名 - 01`、`01 - 題名`、`[01]`、全角数字に対応。動画を先に追加した場合の作品選択後の照合、作品変更後の再照合、手動編集・除外・作品単位の保持、曖昧候補と実行中の変更拒否をテスト。UIで未割り当てを再マッチし、手動選択を保持する操作を確認。
- MKVの開始時刻保持: 開始時刻が約5秒の動画・チャプターを持つ結合テストを追加。`-copyts -avoid_negative_ts disabled`で元のタイムラインを保持し、開始時刻・チャプター位置・元動画の不変を検証。FFmpeg 8.1と公式ソースから検証専用にビルドした6.1.1で、Rust27件すべて成功。6.1.1では修正前にチャプターが0.000–0.900秒から0.023–0.923秒へ移動することを再現し、修正後に元の時刻が保持されることを確認。
- MP4のQuickTimeチャプター回帰テストを追加。チャプタートラックの言語 `und` が再生成で `eng` になるケースを確認し、映像・音声の符号化済みパケットのハッシュ、元動画のバイト列、チャプターのタイトル・時刻、Annictタグを検証。字幕や一般データの欠落、チャプター改変は引き続き拒否。提供された動画そのもの・Windowsでの同動画の処理は未検証です。
- `cargo fmt --check`、`cargo clippy --all-targets -- -D warnings`: 成功。
- フロントエンドの本番ビルド、LinuxのTauriリリースビルド（`--no-bundle`）: 成功。
- cargo-xwin 0.23.1による `x86_64-pc-windows-msvc` のTauriリリースビルド（`--no-bundle`）: 成功。フロントエンドも再ビルドし、`file` / `llvm-readobj` でPE32+・AMD64・Windows GUI形式を確認。出力は `src-tauri/target/x86_64-pc-windows-msvc/release/animeta.exe`（15,003,136 bytes）。説明をダイアログへ整理した最新UI、MP4チャプター処理の修正、自動エピソードマッチング、字幕・チャプター削除、コピー／上書きの選択、保持トラックに基づく再生時間の検証、元タイムラインの保持を含めて再ビルド済み。SDKライブラリのPDB不足によるLNK4099警告は出ていますが、リンクは成功しています。
- Linuxの仮想X画面でネイティブアプリを起動し、初期化・アプリ用SQLiteの作成を確認。検証は隔離したアプリデータディレクトリと資格情報ストア未接続の環境で実施。

## 未検証・保証範囲

- Windowsの実機操作、macOSのビルド・実機操作は未検証です。Windows向けにはLinuxからのクロスビルドを確認済みです。OS別の資格情報ストアはそれぞれのバックエンドを設定済みですが、実際の保存・削除には各OSでの確認が必要です。
- 本物のAnnictトークンによる認証・検索は未検証です。クエリはAnnictの公開ソースに合わせ、HTTPモックで応答処理を検証しています。
- OSの資格情報ストアへの永続保存は、この検証環境では未検証です。サービスが利用できない場合のセッション保持を実装しています。
- ネイティブアプリ上での全操作の自動化は行っていません。画面の操作テストはChromiumで実施し、メディア処理はRustの結合テストで確認しています。
- FFmpegによる再多重化では、コンテナ内の任意の独自情報をすべて保持できることまでは保証しません。対象タグ、ストリーム、添付ファイル、チャプター、既知のトラック情報を検証し、確認できない出力は確定しません。
- 特定プレイヤー・メディアサーバーでのタグ表示、署名・公証、インストーラー配布は初版の検証対象外です。

## 再現用コマンド

```sh
bun run check
bun run test
bun run test:ui
ANIMETA_TEST_FFMPEG=/path/to/ffmpeg ANIMETA_TEST_FFPROBE=/path/to/ffprobe \
  cargo test --manifest-path src-tauri/Cargo.toml
cargo fmt --manifest-path src-tauri/Cargo.toml --check
cargo clippy --manifest-path src-tauri/Cargo.toml --all-targets -- -D warnings
bun run tauri build --no-bundle
bun run tauri build --runner cargo-xwin --target x86_64-pc-windows-msvc --no-bundle
```
